# Shared task events - coordinated LuigiBot/Luigi Web plan

## Ownership and rollout

LuigiBot owns the shared task schema and migration version. Luigi Web must not
create `task_events`, alter shared tables, or bump `schema_version`. The bot
migration must support both SQLite and PostgreSQL using its existing migration
framework. Luigi Web detects the contract and remains compatible with the
legacy task tables while the migration is rolled out.

The existing Discipline v2 plan already reserves a future schema migration.
Before implementation in LuigiBot, choose one coordinated release version for
both migrations if neither has shipped; otherwise assign task events the next
available schema version. Do not create two unrelated migrations with the same
version number.

## Version 1 schema contract

`task_events` is an append-only generic ledger. Version 1 writes `completed`
and `completion_reversed`; later releases may add reopen, snooze, archive,
status-change, and generated-task events without replacing the table.

| Column | Contract |
|---|---|
| `event_uuid TEXT` | Durable primary key generated by the writer |
| `operation_uuid TEXT` | Required unique idempotency key |
| `event_type TEXT` | Initially `completed` or `completion_reversed` |
| `source_task_uuid TEXT` | Stable task/recurring-task UUID |
| `source_table TEXT` | `tasks` or `recurring_tasks` |
| `task_snapshot TEXT` | Display snapshot retained after rename/deletion |
| `catagory_snapshot TEXT` | Optional category snapshot; spelling is intentional |
| `occurred_at TEXT` | Immutable ISO actual event timestamp |
| `effective_date TEXT` | Optional bare `YYYY-MM-DD` for calendar semantics |
| `due_date_snapshot TEXT` | Optional due date at completion time |
| `actor_source TEXT` | `web`, `bot`, `assistant`, or reviewed client id |
| `related_event_uuid TEXT` | Completion referenced by a reversal |
| `details_json TEXT` | Structured event-specific before/after values |

Required constraints and indexes:

- primary key on `event_uuid`;
- unique constraint on `operation_uuid`;
- index on `(source_table, source_task_uuid, occurred_at)`;
- index on `(event_type, effective_date)`;
- index on `related_event_uuid`;
- no foreign key to current task rows, because deleting a task must not delete
  its history.

## Transaction contract

- A state transition into Completed updates the task row, writes one
  `completed` event, and creates matching follow-up tasks in one transaction.
- Retry with the same operation UUID returns the existing event.
- Undo/reopen appends one linked `completion_reversed` event. It never edits or
  deletes the original completion timestamp.
- Once the table exists, event permission/write failures roll back the task
  transition rather than reporting partial success.
- Before migration, current task completion remains available and Admin health
  reports completion history as unavailable.

## Effective dates

Actual `occurred_at` is immutable. `effective_date` initially equals the
server-local calendar date. The Done on time milestone adds the configured
after-midnight cutoff and an explicit override. Recurring schedules and
Calendar completion history use effective date; audit ordering uses actual
timestamp.

## Cross-client rollout

1. Agree on schema version with the Discipline migration.
2. Add LuigiBot SQLite/PostgreSQL migration and idempotent event helpers.
3. Add bot tests for complete/reverse/retry and recurring reactivation.
4. Deploy schema migration while Luigi Web remains legacy-compatible.
5. Deploy Luigi Web dual-write adapter and verify Admin storage health.
6. Enable Calendar Completed layer only after both writers are verified.
7. Backfill current completed rows only with an explicit operation id and
   `actor_source='migration'`; historical recurring completions cannot be
   reconstructed from cleared `completed_time` and must not be guessed.
