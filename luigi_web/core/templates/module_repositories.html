Deployment setup

Repository permissions are configured once by the deployment administrator, outside the web environment editor.

  1. Set LUIGI_WEB_MODULE_REPOSITORY_OWNERS to approved public GitHub owners, separated by commas, to permit source registration. Leave it unset to disable registration.
  2. Alternatively, use LUIGI_WEB_MODULE_REPOSITORIES_FILE for a deployment-owned version-1 JSON policy with a sources list. Each source has id, module_id, and a public HTTPS GitHub repository. Distribution, package, and route namespace are constrained by the backend. The policy must be protected against modification by the web process.
  3. Review the publisher and release code. Register an approved source, then queue an exact release tag, pure Python wheel filename, and independently verified lowercase SHA256.
  4. A separate deployment worker processes one queued request per invocation using python -m luigi_web.core.module_installer --pending. This page does not start it.
  5. Refresh to check the result. Installation and rollback select a candidate for the next process start. Restart through deployment controls, then manage enablement in Modules. This manager's verified releases use the repository approval. External packages installed outside this manager still require LUIGI_WEB_EXTERNAL_MODULES.

Modules execute with application privileges after activation. A checksum pins an artifact; it does not establish that its code is trustworthy. No policy means installation is disabled.
